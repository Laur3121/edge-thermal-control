# sim_tradeoff(案D:ファン稼働率と最高温度の交換関係、シミュレーション)

実機の実験ではない。`scripts/sim_tradeoff.py`(冒頭に、結果を見る前に決めた条件を記載)。

## 条件

- 対象:ノード A(raspi1)。実機役のモデル = 11/13 のステップ実験(案B)、制御器のモデル = 11/14 夜間データ(`scripts/control_params.json`)。別のデータで同定したモデルどうし
- ノイズ:プロセス qT = 0.25、観測 R = 0.068(11/14 の値)。seed 固定、全方式で同じ乱数
- 室温 20℃、Tlimit 80℃、最小 ON 30 秒、ヒステリシス 1℃(比較実験と同じ)
- 負荷:比較実験と同じパターン(20 分)と、ランダム 3 本(区間 2〜10 分、0〜4 コア、各 3 時間)
- 動かした設定:しきい値 T_on 60〜79℃(T_off = T_on − 5)、固定マージン 0〜8℃、提案 α 0〜5

## 結果(`tradeoff.png`、`results.csv`)

- 3 方式の曲線はほぼ重なる。同じ最高温度で比べると、予測を使う 2 方式はしきい値方式より稼働率が数ポイント低い程度(80℃ を超えない中で最も稼働が少ない設定:比較パターンで 提案 20.0% / しきい値 22.9%、ランダム 3 本で 11.8 / 15.7%、4.6 / 5.5%、3.6 / 7.2%)。ただしこの「最も少ない設定」はパターンごとに後から選んだ値なので、曲線全体で見るのが正しい
- 提案と Self-only + 固定はほぼ同じ曲線(σ が一定のため、11/14 の評価と同じ)
- 常時 ON は稼働 100% で最高 66〜69℃、ファンなしは 85〜88℃
- 曲線の位置を決めているのは方式より「どこまで 80℃ に近づけるか」(α・マージン・T_on の値)

## 解釈(仮説)

PoE+ HAT のファンは 5 秒以内に効き、効果も大きい(2 コアで約 24℃ 下がる)。こういう「速くて強い」操作量では、温度を見てから回しても間に合うので、予測の利点は小さい。予測が効くのは、効くまでに時間がかかる操作量(部屋のファン、箱の外のファン、マイグレーション)のはず → シミュレーションでファンの効きを遅くして確かめられる(未実施)
