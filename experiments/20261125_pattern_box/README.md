# pattern_box(干渉が起こる条件:段ボールで囲った状態)

`20261125_pattern_open` と同じシナリオを、ラック全体を段ボール箱で囲って回す。囲いがあると干渉が出るか、出るならどの位置関係・熱量で出るかを、開いた状態と比べる。
生ログ(raw/、events.csv)は編集しない。

## 条件(2026-11-25 朝、実行前に決めた)

- シナリオ・ノード・負荷・ファンは `20261125_pattern_open` と同じ(HAT は r1・r2・r3・r6・r7、r4・r5・r8 は熱源だけ)
- 囲い:段ボール箱(外寸の表示 307 × 220 × 120 mm)を、ラック全体(Pi 8 台と PoE スイッチ)に上からかぶせる。ほぼ隙間のない大きさ。上と横は閉じ、空気の出入りは下(机との間)のケーブルが出ている隙間だけ。IPSJ のときの密閉した容器に近い条件として選んだ
- 温度計:防水温湿度計 1 はラックの上(箱の中、熱い空気がたまる位置)、2・3 はラックの正面(箱の中。横はラックの壁があるため)。ハブ 2 は箱の外(部屋)
- 室温の補正にはハブ 2(部屋)を使う。箱の中の温度(1〜3)は「箱全体の昇温」として別に示す

## 安全と切り替えのルール(実行前に決めた)

1. 箱をかぶせたら、負荷なしで落ち着くのを待つ(シナリオの落ち着き待ち、最大 30 分)
2. **最初の負荷のブロックの前に、箱の中(1〜3 のどれか)が 40℃ を超えたら、密閉は使えないと判断する。** 実験を止め、箱の正面の垂れているフラップを上に折り上げて前面を開けた状態で、最初からやり直す(フォルダを `20261125_pattern_box_front_open` に分ける)
3. 実験中に箱の中が 50℃ を超えたら、`scripts/box_watchdog.py` が実験を止める(負荷が止まり、ファンは OS の自動制御に戻る)。止まった時刻とブロックを書く。Raspberry Pi の動作保証の周囲温度(0〜50℃)と、PoE スイッチも箱の中にあるため

## 指標と判定

`20261125_pattern_open` と同じ。加えて
- 箱全体の昇温:各ブロックの負荷の最後 60 秒 − 負荷の直前 60 秒の、箱の中の温度(1〜3)の変化
- 隣の排熱か箱全体の昇温かの区別:負荷をかけていないノードの上昇から、箱の中の温度の上昇を引いた値を並べる(近いノードだけ大きければ「隣の排熱」、全部同じなら「箱全体の昇温」)
- 予想:アイドルでも箱の中は部屋より 20℃ 前後高くなる(11/25 06:48 に箱を当てたとき、ラックの上の温度計が約 0.6℃/分で上がった)。8 台に負荷をかけるブロックで 50℃ を超え、途中で止まる可能性がある

予想が外れても全部書く。

## 予測の比較(2026-11-25 07 時台、結果を見る前に決めた)

先生の問い「干渉が起きたとき、それを考慮してうまく予測できるか」と、レオの疑問「箱の中の干渉は、箱の中の空気が温まるだけではないか」に答えるため、30 秒先の温度の予測を 3 つのモデルで比べる。開いた状態(`20261125_pattern_open`)でも同じことをする。

- モデル:① 自ノードだけ(室温 = 部屋のハブ 2) ② KF + H(室温 = ハブ 2、H は隣接ノードの温度から) ③ 自ノードだけ(室温 = 箱の中の温度計 1)
- 同定:前半の 3 ブロック(off_r6、off_r7、off_bottom。負荷と休みの全区間。ファンは全台 OFF)
- 評価:後半のファン OFF の区間(off_all、cool_alone_load、cool_nbrs_load と、それぞれの後の休み。fanA_r6_rest も含む)。ファンが ON の区間(fanA_r6_pre・_load、cool_*_fan)は、ファンの係数をこのデータで同定できないため評価から外す
- 対象:8 台すべて(温度の予測には HAT は要らない)。主に見るのは上段(r1〜r3)
- 指標:30 秒先の平均絶対誤差(MAE)。① と ② の差が 0.3℃ 以上で「H で予測が良くなる」。② と ③ を比べ、③ が ② と同じかそれより良ければ「箱の中の干渉は箱の中の温度で説明できる(H の役割は、箱の中の温度計がないときの代わり)」と書く
- 隣接ノードの定義:縦・横・斜めで接する HAT 付き・なしのノードすべての平均(位置によって数が違う)

## 実行の記録

- 10:29ごろ:レオが段ボールをかぶせた(pattern_open は 09:55 に正常終了)。箱の下側は開いている(ラックの脚の部分。完全な密閉ではない)
- 温度計:1 はラックの上(箱の中)。2・3 は箱の正面の内側(箱の下の開口に近く、外気が入る位置。2・3 の値は箱の中の空気より低めに出る可能性がある)。ハブ 2 は箱の外(部屋)
- 10:31 開始(`experiments/pattern_box_run.log`)。8 台とも etc-agent を再起動。見張り `box_watchdog.py --limit 50` を同時に起動(`experiments/pattern_box_watchdog.out`、`box_watchdog.log`)
- 10:36 落ち着き待ち 5 分目:温度計 1 = 30.5℃、2 = 23.6℃、3 = 26.3℃、ハブ 2 = 20.1℃
- 温度計 1 はアイドルのまま約 0.5℃/分で上がり続けた(10:42 34.9、10:46 37.5、10:49 39.1℃)。40℃ を超えるのは確実で、レオが席を外す必要があったため、40℃ に達する前の 10:49 に止めた(SIGINT。負荷のブロックは 1 つも始まっていない)。ルール 2 に従い、前面を開けてやり直す → `20261125_pattern_box_front_open`
- このフォルダには落ち着き待ちの間のデータだけがある(箱を閉じた状態のアイドルの温まり方として使える)

## 結果(負荷なしの落ち着き待ちの間だけ、10:31〜10:49)

負荷のブロックは 1 つも行っていない。開始時はファンを OS に戻した直後で、各ノードは冷えた状態から始まっている(開いた状態のアイドルは HAT ノードで 56〜61℃)。

| | 開始 | 10:49(18 分後) |
|---|---|---|
| 温度計 1(ラックの上、排気が当たる位置) | 27.1℃ | 39.1℃(約 0.5〜0.7℃/分で上昇中) |
| 温度計 2・3(箱の正面の内側、下の開口に近い) | 23.6・26.1℃ | 24.3・27.5℃ |
| 部屋(ハブ 2) | 20.1℃ | 20.3℃ |
| 上段 r1・r2・r3 | 52.6・51.5・52.9℃ | 66.9・67.7・70.9℃ |
| 下段 r5・r6・r7・r8 | 48.7・52.4・52.0・46.9℃ | 55.9・67.5・66.2・54.0℃ |

- 閉じた箱では、負荷なしでも上段のノードが 18 分で 66〜71℃ に達し、まだ上がり続けていた。開いた状態のアイドル(56〜61℃)より約 10℃ 高い
- HAT のない r5・r8 の上がり方は小さい(+7℃)。HAT ノードは HAT 自体の発熱と、ファンを止めていることの影響がある可能性
