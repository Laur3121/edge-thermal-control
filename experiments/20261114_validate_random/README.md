# validate_random

検証用のランダム負荷・ファン(seed=20261114、scripts/scenarios/gen_validate_random.py で生成)。全ノードに独立に、区間 2〜10 分、ファン OFF なら負荷 0〜2 コア、ON なら 0〜4 コア。82℃ 以上はノード側で強制ファン ON(ログの failsafe 列)。

自動生成した雛形。実験の前後に埋める。生ログ(raw/、events.csv)は編集しない。

## 条件

- 日時:2026-11-14 00:36 開始(温度が落ち着くまで約11分待ち)〜 06:02 終了(約5.4時間)。レオは就寝中、無人で実行
- ノード:A=raspi1, B=raspi2, C=raspi3
- 配置・距離:`20261113_step_identify` と同じ(ラック上段、左から raspi1 | raspi2 | raspi3)。間隔は未計測(11/14 に測る)
- 筐体の状態:ラックのみ、囲いなし。PoE 給電、PoE+ HAT 装着
- 室温(ハブ2):21.1℃ → 19.7℃(平均 20.2℃、夜間に 1.4℃ 低下)。温湿度計 1(ラックの上)は 25.8〜28.8℃
- CPU ガバナ:performance(etc-agent の起動時に固定)
- 他のノードの状態:raspi4〜8 は電源のみ(この実験では使わない)

## 結果の概要(`results/phase_summary.csv`、`results/timeseries.png`)

- 最高温度:raspi1 78.9℃、raspi2 75.5℃、raspi3 75.5℃。80℃ 未満で、強制 ON(failsafe)は 0 回
- クロック:全ノード・全区間で 1.8 GHz のまま(スロットリングなし)
- `throttled` 列:raspi1 だけ全区間 `0x80000`。これは「起動後に一度ソフト温度上限に達したことがある」という**過去の履歴を示すビット**(bit 19)で、今起きているスロットリング(下位ビット)ではない。11/13 の実験でも同じ値。再起動で消える。解析では下位ビット(0x0F)とクロックで判断する
