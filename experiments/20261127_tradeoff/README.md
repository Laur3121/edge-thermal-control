# tradeoff(実験 A:遅れありで、しきい値と提案の設定を振って交換関係を比べる)

2026-11-27 夕。条件・判定・予想は、この README を書いた時点(実行前)で決めた。結果は外れても全部書く。生ログは編集しない。
これは 12 月の予備の実験(本番は後で 2 日で撮り直す。docs/tasks.md「12 月の進め方」)。

## 本筋のどこを支えるか

結果 ③「冷却が遅いほど予測が効く」。実験のレビュー(docs/review-experiments-2026-11-27.md)の一番の弱点 1:「しきい値を下げれば済むのでは」に実機で答える。
open_delay60 は、しきい値 75/70℃ と提案(α = 2、δ = 0.5)を 1 組ずつ比べただけで、提案は 80℃ 超えを 3 割減らしたが、稼働は +3.8 ポイント多かった。これが「予測の効果」なのか「ファンを少し多く回しただけ」なのかを、設定を振った交換関係(稼働率 対 80℃ 超え)で分ける。

## 方法

- open_delay60・delay_sweep と同じ仕組み:制御用 PC が決めたファンの指令を d 秒あとにノードへ送る。ノードの強制 ON(82℃)は遅らせない。提案は遅れを知っている(先読み 30 + d 秒)
- 設定(6 つ):
  - しきい値:th65(65℃ ON・60℃ OFF)、th70(70・65℃)、th75(75・70℃、今までと同じ)
  - 提案:pd0p5(δ = 0.5℃、今までと同じ)、pd3(δ = 3℃)、pd6(δ = 6℃)。α = 2 は変えない
  - 提案は α でなく δ を振る:σ がほぼ一定なので、α を 1〜3 と変えても点がほとんど動かない(実行前のシミュレーションで確認:遅れ 60 秒で稼働 52.6〜55.2%、80℃ 超え 920〜930 秒)
- 方式名の後ろに設定を付ける書き方を追加した(`threshold@t_on=65,t_off=60`、`proposed@delta_margin=3`。`scripts/run_experiment.py` の split_mode、`gen_box_control.py` の cond_value、テストあり)
- 各設定 2 巡、巡ごとに順番はランダム
- 配置:囲いなし、10 インチラック 2 段 × 4 列、8 台とも PoE+ HAT、ON は段階 4
- 負荷:open_control・open_delay60・delay_sweep と同じ 20 分のパターン(1 → 4 → 0 → 4 → 2 → 4 コア)、8 台同時、12 分休み
- パラメータ:`scripts/control_params_open.json`(delay_sweep と同じ)
- シナリオ:`gen_box_control.py --ctrl-only --conds th65 th70 th75 pd0p5 pd3 pd6 --seed 20261128<d> --fan-delay <d>` → `scripts/scenarios/tradeoff_d{60,30}.json`(各 約 6.5 時間 + 落ち着き待ち)
- 出力:`experiments/20261127_tradeoff/d60/`(と、下の分岐で d30/)
- **判定は r5 を除く 7 台**(ファンの不調、11/26。r5 は 11/26 から常時 ON でも 85.7℃)。8 台の値も書く

## 指標と判定

指標は `analyze_box_control.py` と同じ(稼働率はノードの実際のファンの状態、80℃ を超えた時間、最高温度、強制 ON、クロック低下)。判定は `scripts/judge_tradeoff.py`(実行前に作成)。

- しきい値の 3 点を「稼働率 → 80℃ 超え(7 台・2 巡の合計)」の折れ線にし、提案の各点と**同じ稼働率**でのしきい値の 80℃ 超えを線形補間で求める。比 = 提案 / しきい値
- 提案の点の稼働率が、しきい値の 3 点の範囲の外なら、その点は「比べられない」
- **予測の意味あり(yes)**:比べられる提案の点のうち 2 点以上で比 ≤ 0.7
- **意味なし(no)**:2 点以上で比 ≥ 1.0
- **はっきりしない(unclear)**:それ以外

## 予想(実行前)

実際のパラメータ(control_params_open.json)の 7 台で、閉ループのシミュレーションを 2 回ずつ回した(`simulate`、室温 20℃、開始 58℃、ノイズ 0.3℃)。7 台・2 巡の合計:

| th65 | 68.4% / 305 秒 | 約 71% / 約 250 秒 |
| th70 | 57.8% / 1625 秒 | 約 60% / 約 1300 秒 |
| th75 | 50.0% / 2955 秒 | 約 53% / 約 2400 秒(open_delay60 の実機 52.6% / 2374 秒) |
| pd0p5 | 54.6% / 930 秒 | 約 56% / 約 1600 秒(open_delay60 の実機 56.4% / 1603 秒) |
| pd3 | 58.8% / 730 秒 | 約 61% / 約 1250 秒 |
| pd6 | 62.3% / 395 秒 | 約 64% / 約 700 秒 |

- 「実機に合わせた予想」:open_delay60 の実機とシミュレーションの同じ設定の比(80℃ 超え:しきい値 0.8 倍、提案 1.7 倍。稼働:しきい値 +2.6、提案 +1.8 ポイント)を、同じ方式の他の設定にも掛けたもの

## A'(負荷が徐々に上がる版、11/27 夕に追加。実行前に決めた)

### 本筋のどこを支えるか

結果 ③。open_delay60 で提案が 80℃ を超えた原因のほとんどは、負荷が一気に(1→4、0→4 コア)上がることだった(提案は「今の負荷が続く」と仮定するため)。実際の負荷が徐々に上がるなら結果がどう変わるかを見て、「予測が効く条件」を遅れだけでなく負荷の上がり方でも示す。今の一気に上がる負荷は「最も厳しい条件」として並べる。

### 方法

- A(d60)と同じ。違いは負荷だけ:4 コアに上がる所を 1 分ごとに 1 コアずつにした(1 → 2 → 3 → 4、0 → 1 → 2 → 3 → 4、2 → 3 → 4)。各ブロックの長さ(20 分)は同じ。そのため 4 コアの時間は短くなる(負荷の合計は少し小さい)
- シナリオ:`gen_box_control.py --ctrl-only --ramp --conds th65 th70 th75 pd0p5 pd3 pd6 --seed 2026112961 --fan-delay 60` → `scripts/scenarios/tradeoff_ramp_d60.json`(約 6.5 時間)
- 出力:`experiments/20261127_tradeoff/ramp_d60/`。A(d60、yes なら d30)が終わったあとに `scripts/next6_tradeoff_ramp.sh` が自動で始める
- 判定は r5 を除く 7 台

### 指標と判定

- 主:A と同じ `judge_tradeoff.py`(同じ稼働での 80℃ 超えの比)
- 副:80℃ 超えが 7 台・2 巡の合計で 60 秒以下の設定のうち、一番少ない稼働率を方式ごとに出す。提案がしきい値より 5 ポイント以上少なければ「80℃ を守ったまま稼働を減らせた」。どちらかの方式で 60 秒以下の設定がなければ「比べられない」

### 予想(実行前)

シミュレーション(A と同じ設定。11/27 夕に 82℃ の安全装置もシミュレーションに入れた。安全装置ありでは、open_delay60 のしきい値の実機 52.6% / 2374 秒をよく再現する:53% / 2345 秒。提案は実機 1603 秒に対し 750 秒で、実機の方が約 2 倍悪い。原因は未確認で、H の部分を疑っている)。7 台・2 巡の合計:

| 設定 | 一気(A、参考) | 徐々(A') | 徐々・提案の 80℃ 超えを実機に合わせて 2 倍 |
|---|---|---|---|
| th65 | 69% / 265 秒 | 62% / 0 秒 | 同じ |
| th70 | 59% / 1335 秒 | 47% / 235 秒 | 同じ |
| th75 | 53% / 2345 秒 | 38% / 1670 秒 | 同じ |
| pd0p5 | 55% / 750 秒 | 37% / 765 秒 | 約 1500 秒 |
| pd3 | 59% / 590 秒 | 43% / 325 秒 | 約 650 秒 |
| pd6 | 62% / 345 秒 | 52% / 0 秒 | 0〜100 秒 |

- 徐々に上がる負荷では、どちらの方式も稼働が 10〜15 ポイント減る
- 主の判定:シミュレーションのままなら yes(pd3 の比 0.36、pd6 は 0。pd0p5 はしきい値の範囲外)。2 倍にすると pd3 の比 約 0.75、pd6 は 0〜0.6 で unclear〜yes
- 副の判定:シミュレーションでは、60 秒以下の一番少ない稼働は提案 52%(pd6)、しきい値 62%(th65)で、10 ポイント少ない
- **Claude の予想:主は unclear〜yes、副は「80℃ を守ったまま 5〜10 ポイント減らせた」**。一気に上がる負荷(A)より、提案に有利な結果になる
