# compare

比較実験(seed=20261114、scripts/scenarios/gen_compare.py で生成)。5 条件 × 3 巡、各巡の順番はランダム:[['proposed', 'selffixed', 'threshold', 'always', 'nofan'], ['threshold', 'nofan', 'selffixed', 'always', 'proposed'], ['threshold', 'nofan', 'proposed', 'always', 'selffixed']]。3 台に同じ条件・同じ負荷。負荷パターン(コア数, 秒)=[(1, 120), (4, 360), (0, 180), (4, 300), (2, 120), (4, 120)]、休み 720 秒。合計 約 8.1 時間

自動生成した雛形。実験の前後に埋める。生ログ(raw/、events.csv)は編集しない。

## 条件

- 日時:2026-11-14 17:23 開始(温度が落ち着くまで約 33 分待ち)〜 11/15 01:40 終了
- ノード:A=raspi1, B=raspi2, C=raspi3。3 台に同じ条件・同じ負荷を同時に。3 巡 × 3 台 = 各条件 9 回
- 配置:ラック上段、左から raspi1 | raspi2 | raspi3(間隔は未計測)。PoE 給電、PoE+ HAT 装着
- 筐体の状態:ラックのみ、囲いなし
- 室温(ハブ2):22.1℃ → 22.6℃(22.0〜22.6℃、平均 22.3℃)
- CPU ガバナ:performance(etc-agent の起動時に固定)
- 制御:`scripts/control_params.json`(11/14 夜間データで同定、c = 0)。Tlimit 80℃、Δ 30 秒、α 2、δ 0.5℃、ヒステリシス 1℃、最小 ON 30 秒。しきい値方式は 75℃ ON / 70℃ OFF(レオ確認済み)。ノード側の強制 ON は 82℃ 以上・指令途絶 10 秒
- 他のノード:raspi4〜8 は電源のみ

ノード別のファン稼働率(提案 / しきい値):A 45.6 / 43.6%、B 32.5 / 37.0%、C 37.4 / 38.3%。開始温度は全条件 57.1〜57.7℃ でそろっている。

- **予測を使う 3 方式とも、80℃ 超過・スロットリング・強制 ON は 0。** 常時 ON と比べて稼働を 55〜62% 減らした
- **提案としきい値方式はほぼ同じ**(稼働 38 vs 40%、最高温度 78.7 vs 78.4℃)。ノードによって大小が入れ替わり、一貫した差はない。事前に決めた着地「同じ稼働でより安全か」でも差はない
- Self-only + 固定は、固定マージン(約 3.5〜5℃)が提案(約 2.5℃)より大きいぶん、安全側(最高 76.8℃)で稼働が多い(45%)。σ が一定なので、提案と固定の違いはマージンの大きさ=交換関係の曲線上の位置の違いであり、方式の優劣ではない
- シミュレーション(`experiments/20261114_sim_tradeoff`)の「3 方式の曲線はほぼ重なる」と一致。PoE+ HAT のファンは速くて強いので、温度を見てから回しても間に合う、という仮説と合う
- ファンなしは 20 分のうち約 11.6 分 80℃ を超え、約 2.7 分スロットリング。82℃ の強制 ON が働いて 83.8℃ で止まった
