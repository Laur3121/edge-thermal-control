# pattern_box_front_open(段ボール箱、前面を開けた状態)

`20261125_pattern_box`(箱を閉じた状態)が、負荷なしの落ち着き待ちの間に箱の中 40℃ に迫った(10:49 に 39.1℃、約 0.5℃/分で上昇中)。実行前に決めたルール(box の README の安全のルール 2)に従い、箱の正面を開けて、同じシナリオを最初からやり直す。
生ログ(raw/、events.csv)は編集しない。

## 条件

- `20261125_pattern_box` と同じ(シナリオ、配置、負荷、ファン、温度計の位置、指標と判定、予測の比較)。違いは囲いだけ
- 囲い:段ボール箱をラック全体にかぶせ、**正面(ポート側、温度計 2・3 を置いた側)を開けた**。下(ラックの脚の部分)も開いている
- 安全:50℃ で `box_watchdog.py` が止める(同じ)
- 予想(レオ):前面を開けても箱の中の温度はあまり下がらない

## 実行の記録

- 10:52ごろ:レオが正面のフラップを上に折り上げた。折り上げた後も、正面から見て**上段(r1〜r4)は箱に隠れたまま、下段(r5〜r8)だけが出ている**(レオ「蓋をしてる感じ」)。つまり上段は囲われ、下段は正面が開いた「半分囲う」状態
- 10:53 開始(`experiments/pattern_box_front_open_run.log`)。8 台とも etc-agent を再起動。見張り `box_watchdog.py --limit 50` を同時に起動
- 10:53 温度計 1 = 41.5℃(閉じた箱を止めた 10:49 から、前面を開けるまでの間も上がっていた)、2 = 24.6、3 = 27.8、ハブ 2 = 20.5℃
- 10:53〜10:58 下段だけ出した状態で、温度計 1 は 41.4〜41.9℃ と横ばい〜わずかに上昇。負荷なしで 40℃ を超えたままなので、ルール 2 の趣旨(8 台負荷で 50℃ を超えて途中で止まるのを避ける)に従い、上段も出すよう頼んだ
- 10:59ごろ:レオが上段も出した。**最終的な条件:箱は上と左右と後ろを覆い、正面(ポート側)と下が開いている**(上にふたを置き、後ろを塞いだ形)。落ち着き待ちの間の変更で、負荷のブロックの前
- 10:59〜11:05 温度計 1 は 41.9〜42.0℃ で横ばい(上段を出しても下がらなかった。レオの予想どおり)
- 11:05 落ち着き待ち終了 → p0_baseline。11:10 最初の負荷のブロック(off_r6)開始。温度計 1 = 42.2℃。終了見込み 14:06

## 予測の比較に足したもの(11:05、負荷のブロックが始まる前・結果を見る前に決めた)

- 温度計 1(ラックの上)は、縦向きのボードの排気がまっすぐ当たる位置で、「箱の中の空気」より「排気の温度」に近い(レオの指摘)。排気には自ノードの熱も混ざるので、③(室温 = 温度計 1)は「箱の中の空気が温まるだけで説明できるか」を確かめるのに向かない
- そこで ③ はそのまま出したうえで、**③' 自ノードだけ(室温 = 温度計 2・3 の平均)** を足して並べる。ただし 2・3 は正面を開けた後は箱の外に近く(床に置いてある、正面が開いている)、「吸気側の空気」として扱う
- 安全のルール(温度計 1〜3 のどれかが 50℃ で止める)は変えない。温度計 1 で判定するので安全側になる(PoE スイッチも箱の中)

## 結果(14:06 終了、14:10 解析)

最後まで止まらずに終わった(14:06、box_watchdog も上限 50℃ に届かず)。数値は `results/summary.txt`、`results/pred_swap/summary.txt`。

### Q1(実行前に決めた判定:上昇 1℃ 以上で「干渉あり」)

| 負荷 → 見るノード | 上昇 [℃] | 判定 |
|---|---|---|
| 真上 r6→r2 / r7→r3 | −0.45 / +0.50 | なし |
| 横 r6→r7 / r7→r6 | −0.23 / −0.18 | なし |
| 斜め r6→r1 / r6→r3 / r7→r2 | −0.13 / −0.41 / −0.01 | なし |
| 遠い r7→r1 | +0.06 | なし |
| 下段 4 台 → r1 / r2 / r3 / r4 | +1.83 / +0.06 / +0.20 / +1.30 | r1・r4 はあり |

- 箱の中の気温はほぼ一定(温度計 1 は 42〜43℃、2・3 は 25〜27℃)。開いた状態のようなブロックごとの揺れ(±1.5℃)がなく、±0.5℃ に収まった
- 下段 4 台で上がったのは端の r1・r4 だけで、真上の r2・r3 はほぼ 0。理由は分からない(箱の側面に沿った流れ?)
- 負荷前の温度は、開いた状態より上段で raw +9〜13℃(部屋の差 3.7℃ を引いて +5〜9℃)
- r6 だけの負荷で r6 は 83.8℃、強制 ON、1677 MHz(開いた状態は 77℃)
- off_all(8 台):ファン付きの 5 台がすべて 83℃ に達し強制 ON、クロック 1677〜1726 MHz。強制 ON は r1・r2・r3 が 12:16〜、r6 は 11:11〜、r7 は 11:34〜(テレメトリの failsafe 列)。このため off_all − 自分だけ の比較は頭打ちで判定できない

### Q2

- (a) fanA_r6 − off_r6:r2 −0.06、r7 −0.39、r1 −0.29、r3 −0.11 → なし。r6 のファン ON 中、温度計 1 は −1.1℃
- (b) 下がる量:隣が休み 18.06℃、隣も負荷 16.95℃。最後 60 秒(部屋を引く)の差 −0.32℃、生の差 +1.0℃ → 「冷えにくい」とは言えない。ただし ON の前はどちらも約 81℃ で頭打ち(強制 ON/スロットリングの手前)で、ON の時点の差は見えない

### Q3(--swap、上段 r1〜r3 の 30 秒先 MAE [℃])

| モデル | 箱 | 開いた状態(参考) |
|---|---|---|
| ① 自ノードだけ(部屋) | 0.84 | 0.64 |
| ② KF + H(部屋) | 0.44 | 0.39 |
| ③ 自ノードだけ(温度計 1) | 0.53 | 0.69 |
| ③' 自ノードだけ(温度計 2・3) | 0.41 | 0.71 |

- ② − ① = −0.40℃(基準 0.3℃ を超える)。ただし ③' と同じ精度
- 実行前に決めた解釈(pattern_box の README)に従うと「箱の中の干渉は主に箱全体の昇温。H は箱の中に温度計がないときに隣の温度から推定する役割」
- ② の ρ:r1・r3 0.995(探索範囲の上限)、r4・r5・r7 0.96〜0.975。r2・r6 は c < 0 で H を外した(② = ①)
- 箱では部屋(ハブ 2)が 20.7→23.9℃ と動いたが、箱の中の温度計はほぼ一定。① が悪いのは、部屋の変化が箱の中に届いていないためと考えられる
- 8 台平均:① 0.84、② 0.60、③ 0.61、③' 0.50

### まとめ

1 台の排気が隣を直接温める経路は、箱の中でも 0.5℃ 未満。熱は囲いの空気に溜まる形で効き、囲うだけで 5〜9℃、8 台同時で全 HAT ノードが 83℃。
