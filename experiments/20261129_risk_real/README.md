# risk_real(負荷リスクの動的マージン、実機の予備の実験)

2026-11-29 未明。条件・判定・予想は、この README を書いた時点(実行前)で決めた。結果は外れても全部書く。生ログは編集しない。
12 月の予備の実験(本番は r5 を替えてから撮り直す)。

## なぜやるか(本筋のどこか)

③ と手法(動的マージン)。σ がほぼ一定で、動的マージン M = ασ + δ は実際には固定マージンだった(レオに指摘された、11/28)。負荷が上がる確率を入れた動的マージン(負荷リスク)を、実機に近いシミュレーション(`20261128_sim_g2`:実測の条件で A・A' を 12 点中 9〜10 点再現)で比べると、2 つの実機役のどちらでも今の提案(固定 δ)より良かった。実行前の決まりどおり、実機で確かめる。

## 方法

- 負荷リスク(`proposed_risk`、`src/etc/control.py`、11/28 追加、テストあり。シミュレーションの実装と同じ結果になることを確認):先読みの最高温度が 80℃ を超える確率 P = (1 − p) Φ((T̂_一定 − 80)/σ) + p × 平均_{s, u'} Φ((T̂_{s,u'} − 80)/σ) が ε を超えたら ON、ε/2 を下回り最小 ON 30 秒を過ぎたら OFF。モデルと KF は今の提案と同じ(control_params_open.json の withH)
- p(先読み 90 秒の間に負荷が 0.2 以上上がる確率):負荷パターンの記録から決めた値(シミュレーションと同じ):一気 0.24、徐々 0.54。実際の運用では過去の負荷の記録から求めることになる(ノードがその場で学ぶ形は今後の課題)
- 設定(6 つ):しきい値 th70(70/65℃)、今の提案 pd3・pd6(δ = 3・6℃)、負荷リスク pr0p5・pr2・pr10(ε = 0.5・2・10%)
- 遅れ 60 秒(delay_sweep と同じ仕組み)。2 巡、巡ごとに順番はランダム
- 負荷:一気(A と同じ 20 分のパターン、`risk_step_d60.json`、seed 2026112960)と徐々(A' と同じ、`risk_ramp_d60.json`、seed 2026112961)。各 約 6.5 時間、合計 約 13 時間
- 配置:囲いなし、8 台とも PoE+ HAT(段階 4)。**r5 は判定から外す**(ファン不調)
- 出力:`step/`・`ramp/`。`scripts/next8_risk_real.sh` が自動で回し、最後に `scripts/judge_risk.py` を回す

## 判定(実行前に決めた)

- **一気**:負荷リスクの 3 設定のうち 80℃ 超えが一番少ないものが、pd6 の 0.3 倍以下、かつ稼働が pd6 の +10 ポイント以内 →「良い」(固定 δ ではこの負荷で 80℃ を守れなかった。それを少しの稼働の増えで守れるか)
- **徐々**:pd3・pd6 の折れ線と同じ稼働での比の中央値が 0.7 以下 →「良い」、1.0 以上 →「良くない」、それ以外 →「はっきりしない」(負荷リスクの点が範囲外なら「比べられない」)
- **1 つの ε**:pr0p5 の 80℃ 超えが一気・徐々の両方で 120 秒以下 →「守れた」
- 「一気が良い」かつ「1 つの ε で守れた」なら、負荷リスクを本番の提案手法にする。だめなら、動的マージンは成果として言わず、A・A' の結果(固定 δ の曲線)で ③ を書く

## 予想(実行前、`20261128_sim_g2` の第 2 段、実機役 G2 / 1 次。7 台・2 巡の合計)

| 設定 | 一気 稼働 / 80℃ 超え | 徐々 稼働 / 80℃ 超え |
|---|---|---|
| th70 | 63% / 940 秒 ・ 61% / 1700 秒 | 54% / 260 秒 ・ 52% / 400 秒 |
| pd3 | 62% / 1370 ・ 61% / 810 | 49% / 625 ・ 48% / 240 |
| pd6 | 64% / 1035 ・ 64% / 495 | 55% / 60 ・ 55% / 0 |
| pr0p5 | 70% / 125 ・ 72% / 0 | 70% / 0 ・ 71% / 0 |
| pr2 | 64% / 415 ・ 66% / 0 | 66% / 5 ・ 66% / 0 |
| pr10 | 58% / 1300 ・ 57% / 710 | 55% / 75 ・ 53% / 0 |

- 参考に 11/28 の実機:一気 th70 64.7% / 1574 秒、pd3 63.1% / 1598、pd6 65.2% / 1137。徐々 th70 54.4% / 497、pd3 53.1% / 217、pd6 58.5% / 39
- **Claude の予想**:一気は「良い」(pr0p5 が pd6 の 0.1〜0.2 倍、稼働 +6〜8 ポイント)。徐々は、負荷リスクが慎重すぎる側に出て、pr0p5・pr2 は pd6 より稼働が 10 ポイント以上多い。比べられるのは pr10 くらいで「はっきりしない」。1 つの ε は「守れた」(一気 0〜150 秒、徐々 0 秒)
- 注意:シミュレーションは、実機の提案(固定 δ)の 80℃ 超えを一気の負荷で小さめに見積もる(11/28 の実機の 0.5〜0.9 倍)。負荷リスクも同じなら、一気の pr0p5 は 150〜300 秒になり、「1 つの ε」の基準(120 秒)を超えるかもしれない
