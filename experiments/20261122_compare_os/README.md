# compare_os(OS 標準のファン制御との比較)

11/14 の比較実験に、OS 標準のファン制御(step_wise)を比較相手として足す。同じ夜にしきい値方式と提案手法も回し、11/14 の結果の再現も確かめる。
生ログ(raw/、events.csv、control.csv)は編集しない。

## 条件(2026-11-22、実行前に決めた)

- シナリオ:`scripts/scenarios/compare_os.json`(`gen_compare_os.py` で生成)
- 条件:OS 標準 / しきい値(75℃ ON、70℃ OFF)/ 提案(KF、α = 2、δ = 0.5℃、Δ 30 秒)。しきい値と提案の設定は 11/14 と同じ(`scripts/control_params.json`、同定は 11/14 夜間データ)
- OS 標準:負荷パターンの 20 分の間だけ、ファンを OS の自動制御(thermal_zone0 の step_wise)に任せる。トリップポイント 40/45/50/55℃ → 段階 1〜4(11/22 に 3 台で確認)。node_agent に "2"(auto)を送る
- 負荷パターン:11/14 と同じ(コア数, 秒)=(1,120)(4,360)(0,180)(4,300)(2,120)(4,120)。休み 720 秒(どの条件もファン OFF で、開始温度をそろえる)
- 3 台(raspi1 = A、raspi2 = B、raspi3 = C)同時、同じ条件・同じ負荷。3 巡、順番はラテン方格:[threshold, os, proposed] / [os, proposed, threshold] / [proposed, threshold, os]。各条件 9 回
- CPU ガバナ performance(11/14 と同じ。OS 標準の条件でもガバナは固定する。ファンの制御だけを比べるため)
- 安全:82℃ 以上か指令途絶 10 秒でノード側が強制 ON(OS 標準の条件でも同じ)
- 合計 約 4.9 時間 + 温度が落ち着くまでの待ち

## 指標(11/14 と同じ + OS 標準のための指標)

- ファン稼働率:ファンが回っていた時間の割合(段階 1 以上)
- 段階で重みをつけた稼働:段階 / 4 の平均(最大の段階で回し続けたら 100%)。OS 標準は低い段階で回すので、稼働率だけで比べると不公平になるため
- 最高温度、80℃ を超えた時間、スロットリングの時間(get_throttled の bit 3)、強制 ON の時間、ON の回数
- 区間は負荷パターンの 20 分(休みは除く)。11/14 と同じ集計(`scripts/plot_control.py`)

## 予想(実行前)

- OS 標準は 40℃ から回り始めるので、20 分のほぼ全部でファンが回る(稼働率 90% 以上)。最高温度は常時 ON(65℃)に近い。段階の重みで見ると常時 ON より小さい
- しきい値と提案は 11/14 と同じ程度(稼働 約 40%、最高 約 78.5℃、80℃ 超過 0)。差はほぼない

予想が外れても、結果は全部書く。
