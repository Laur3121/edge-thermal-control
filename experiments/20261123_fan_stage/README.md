# fan_stage(ファンの段階を下げたときの比較)

11/14 の比較実験では、ON は常に最大の段階(4)だった。OS 標準は 40〜55℃ で段階 1〜4 を使い分ける。低い段階で足りるなら、騒音や寿命の点で有利かもしれない。
生ログ(raw/、events.csv、control.csv)は編集しない。

## 条件(2026-11-22 夜、実行前に決めた)

- シナリオ:`scripts/scenarios/fan_stage.json`(`gen_fan_stage.py`)
- 条件:しきい値(75℃ ON / 70℃ OFF)で ON は段階 4 / しきい値で ON は段階 2 / 常時 ON で段階 1
  - node_agent の ON の段階を MQTT(etc/<host>/fan/stage/set)で切り替える(2026-11-22 追加)。強制 ON は常に段階 4
- 負荷パターン・休み(ファン OFF)・3 台同時は 11/14 と同じ。3 巡、順番はラテン方格(seed 20261123)。各条件 9 回
- interference_load の後に自動で開始。約 4.9 時間

## 指標と判定(実行前に決めた)

- 指標:最高温度、80℃ 超過の時間、強制 ON の時間、ファン稼働率(ON の時間)、段階で重みをつけた稼働(段階 / 4 の平均)
- 判定:
  - しきい値・段階 2 が、80℃ 超過 0・強制 ON 0 なら「段階 2 で足りる」
  - 常時 ON・段階 1 が、80℃ 超過 0 なら「最も弱い段階でも回し続ければ足りる」
- 予想:段階 2 のしきい値は 80℃ を超えずに済むが、ON の時間は段階 4 より長くなる。段階 1 の常時 ON は 4 コアの負荷が続く区間で 80℃ を超える

予想が外れても全部書く。段階ごとの騒音は測っていないので、「どちらが良いか」は騒音の計測(12 月)と合わせて判断する。
