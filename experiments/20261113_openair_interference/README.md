# 2026-11-13 囲いなしでの熱干渉の予備確認

## 条件

- 日時:2026-11-13 11:51〜12:23(温度が落ち着くまでの待ち 約14分 + 基準 3分 + 負荷 10分 + 休み 5分)
- ノード:左から raspi1(A、ラベル RPi4_020)| raspi2(B、RPi4_004)| raspi3(C、RPi4_003)。机の上に並べただけで、囲いなし
- 間隔:未測定(写真なし)。※この後、位置に印を付けて写真を撮る予定
- 給電:3台とも PoE、PoE+ HAT 装着
- ファン:3台とも OFF(node_agent が OS の自動制御を止めて制御)。A が 82℃ に達したとき1秒だけ強制 ON(安全機能)
- 負荷:A だけ `stress-ng --cpu 2`(CPU 使用率 約50%)を10分
- CPU ガバナ:performance(1.8 GHz 固定)
- 室温:未記録(SwitchBot 温湿度計の設置前)
- シナリオ:`scripts/scenarios/openair_interference.json`、実行:`scripts/run_experiment.py --nodes A=raspi1 B=raspi2 C=raspi3`

## 結果(`results/phase_summary.csv`、`results/timeseries.png`)

| ノード | 基準3分の変化 | 負荷10分の変化 | 負荷中の最高 |
| --- | --- | --- | --- |
| A(負荷) | +0.50℃ | **+21.3℃**(59.1 → 80.4℃) | 82.3℃ |
| B(すぐ隣) | +0.11℃ | **+0.49℃** | 55.5℃ |
| C(2つ離れた位置) | +0.63℃ | +0.50℃ | 61.8℃ |

- **囲いなしでは熱干渉はほぼ見えない**:B の上昇(+0.49℃)は、干渉が届かないはずの C(+0.50℃)と同じで、ファンを止めた後のゆっくりした上昇(基準区間でも続いていた)と区別できない
- 旧データ(IPSJ 時、すぐ隣が +12℃)はタオルをかけて擬似的に囲った状態だった(本人談)。干渉には囲い(排熱がこもる環境)が必要と考えられる
- A はファンなし・2コア負荷で約8分で 80℃ に達した。`get_throttled` は 0x80000(ソフト温度制限が発生した記録)になったが、クロックは 1.8 GHz のまま下がらなかった
- 開始前の「温度が落ち着く」判定は、B・C が 0.1℃/分程度でまだ上がっている状態で通った(ファンを止めてから約14分)。本番では待ち時間を長くするか、判定を厳しくする
