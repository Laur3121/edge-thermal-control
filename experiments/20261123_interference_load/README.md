# interference_load(干渉の条件を広げる:ファン ON・3 台に負荷)

11/13 の干渉の確認は「A だけ 2 コア、ファンは全部 OFF、10 分」の 1 条件だけだった。ファンを回したとき(風で排熱が隣に流れる可能性)と、3 台に同時に負荷をかけたときに干渉が出るかを確かめる。
生ログ(raw/、events.csv)は編集しない。

## 条件(2026-11-22 夜、実行前に決めた)

- シナリオ:`scripts/scenarios/interference_load.json`(`gen_interference_load.py`)
- 配置:ラック上段、左から raspi1(A)| raspi2(B)| raspi3(C)。11/13・11/14 と同じ。囲いなし
- ブロック(順に):ファン OFF で A だけ / B だけ / C だけ / 3 台とも、ファン ON(段階 4)で A だけ / 3 台とも
  - 各ブロック:2 コアの負荷 600 秒 → 休み 720 秒(負荷 0・ファン OFF)
- CPU ガバナ performance、強制 ON は 82℃ 以上か指令途絶 10 秒
- 11/22 の compare_os の後に自動で開始(scripts/run_chain_20261123.sh)。約 2.3 時間

## 指標と判定(実行前に決めた)

- 上昇 = 負荷の最後の 60 秒の平均温度 − 負荷の直前 60 秒の平均温度(室温の変化を除くため、同じ時間の室温の変化を引く)
- (1)3 台に負荷をかけたときの干渉:各ノードの「3 台とも」の上昇 −「自分だけ」の上昇。ファン OFF と ON のそれぞれで
  - 判定:B(真ん中、隣が 2 台)で 1℃ 以上なら「同時に負荷をかけると干渉あり」
- (2)ファン ON での隣への影響:「A だけ・ファン ON」の B の上昇 − C の上昇
  - 判定:1℃ 以上なら「ファンの風で隣に熱が届く」
- 予想:どちらも 1℃ 未満(11/13 の結果と同じく、開いたラックでは干渉はほぼない)

予想が外れても全部書く。
