## 本筋のどこを支えるか

② → ③ のつなぎ。実験のレビュー(docs/review-experiments-2026-11-27.md)の一番の弱点 2:「制御で H あり/なしの差が一度も出ていない」に答える。
③(遅れがあると予測が効く)はこれまで囲いなしで示した。囲いなしでは熱が周りにたまりにくく、H の出番が小さい。① で熱がたまると分かった囲いの中で、H が制御の結果(80℃ 超え・稼働)を変えるかを見る。
もう 1 つ:open_delay60 では、提案の予測が実測より 1.6℃ 低かった(負荷一定・ファン OFF の 90 秒、中央値)。安全装置を入れたシミュレーションでは、しきい値は実機を再現したが、提案は実機の方が約 2 倍悪かった。H の部分が予測を下げている疑いがある(11/27 夕)。H あり/なしで、この予測のずれも比べる。

## 方法

**第 1 段:囲いで同定(ident、約 1.3 時間)**
- これまでの囲いのパラメータ(control_params_box2.json)は、8 台同時の負荷で同定したため、H の効き c が 8 台中 6 台で 0(自分の負荷と周りの熱が区別できない)。台ごとに負荷をずらして同定し直す
- 負荷:台ごとに独立に 0〜3 コア(180 秒ごと)。ファン:台ごとに独立に 60 秒ごと確率 0.5 で ON。60 分 + 休み 10 分(`gen_stagger.py box_ident`、seed 2026112870)。open_ident(囲いなし)と同じ形
- 同定:`fit_control_params_box.py --exp experiments/20261125_pattern_box_front_open <ident> --head-frac 0.6 --out scripts/control_params_box3.json`(11/25 の囲いの 1 台ずつ負荷のデータ + ident の前半 6 割)
- 確認:`check_params_holdout.py`(ident の後半 4 割で、係数の符号と 30 秒先の誤差。基準は 11/26 に決めたもの)。**NG なら第 2 段は回さない**
- **c > 0 が 7 台(r5 を除く)中 3 台未満なら、第 2 段は回さない**(H あり/なしが同じ制御になり、比べる意味がない)

**第 2 段:制御の比較(ctrl、約 3.3 時間)**
- 方式:しきい値(75/70℃)/提案(KF + H、α = 2、δ = 0.5)/提案の H なし(`pnoh`:自ノードのモデル + 同じ判断・同じマージン。`ControlConfig.use_h = 0`、11/27 追加、テストあり)
- 遅れ 60 秒(delay_sweep と同じ仕組み)。提案はどちらも遅れを知っている
- 負荷:台ごとにランダム(0〜4 コアを 120 秒 × 10 区間、seed 2026112871。box_control_rload と同じ形。囲いの中で常時 ON の最高 76.4℃ で、ファンの余力がある)。同じ表を全方式・全巡で使う
- 2 巡、順番は巡ごとにランダム(seed 2026112872)
- パラメータ:第 1 段の control_params_box3.json

**共通**
- 囲い:`20261125_pattern_box_front_open` と同じ形(段ボール箱で上・左右・後ろを覆い、正面(ポート側)と下が開いている)。温度計 1 はラックの上(箱の中)、2・3 は正面の内側、ハブ 2 は箱の外(部屋)
- 安全:`box_watchdog.py --limit 50`(箱の中が 50℃ で止める)。ノードは 82℃ で強制 ON
- **r5 はファンが不調なので、負荷 0・ファン OFF(アイドルのまま置く)。判定は r5 を除く 7 台**
- 自動実行:`scripts/next7_box_hcheck.sh`。next6(A')が終わり、レオが箱をかぶせたら(Claude が `experiments/BOX_ON` を作る)始める

## 指標と判定(実行前に決めた)

指標は `analyze_box_control.py` と同じ(稼働率、80℃ を超えた時間、最高温度、強制 ON)。7 台・2 巡の合計。

- **主:H が制御で効くか**(提案 H あり = P、H なし = N)
  - **効く**:P の 80℃ 超えが N の 0.7 倍以下、かつ P の稼働が N の +3 ポイント以内。または、80℃ 超えが同程度(0.7〜1.3 倍)で P の稼働が N より 3 ポイント以上少ない
  - **逆効果**:P の 80℃ 超えが N の 1.3 倍以上で稼働が多くない、または稼働が 3 ポイント以上多くて 80℃ 超えが少なくない
  - **差なし**:それ以外
  - N と P の 80℃ 超えがどちらも 60 秒未満なら、稼働だけで比べる(3 ポイント以上の差で「効く」/「逆効果」)
- **副:予測のずれ**(control.csv から、open_delay60 と同じ方法):ファン OFF と判断した時刻のうち、その後 90 秒の負荷がほぼ一定(上がり 0.2 未満)でファンも OFF のままだったものについて、実際の最高 − 予測 の中央値。P と N で比べる。H が囲いの熱を拾えていれば、P の方が 0 に近い
- 参考:しきい値と比べた 80℃ 超えの比(delay_sweep と同じ R)

## 予想(実行前)

- 第 1 段:c > 0 は 7 台中 4〜6 台(囲いなしの open では 7 台とも正だった)。check は通る
- 第 2 段:囲いの中では、部屋の温度を基準にした自ノードのモデル(N)の 30 秒先の誤差は 0.84℃、H ありは 0.44℃(pattern_box_front_open の上段)。N は囲いの温まりを見落として低めに予測し、ファンを入れるのが遅れる → N の 80℃ 超えが P より多い
- 数字の目安(根拠は弱い):しきい値の 80℃ 超え 500〜1500 秒、P はしきい値の 0.6〜0.8 倍、N はしきい値の 0.8〜1.0 倍。稼働の差は 3 ポイント以内
- **Claude の予想:主は「効く」と「差なし」が半々**。H の予測の改善は 0.4℃ で、制御の差になるかははっきりしない。副は、P の予測のずれが N より 0 に近い
- 「差なし」や「逆効果」でもそのまま書く。その場合、本文では「H の成果は温度計なしの推定まで。制御では、囲いの中でも自ノードのモデルと同じ」と書く
