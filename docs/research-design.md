# 研究設計(RQ・仮説・実験計画)

詳細版は Notion「特研2」>「論文構成と予想される結論」。実験はここに書いた RQ を確かめるためだけに回す。

## RQ と仮説

| RQ | 問い | 仮説 | 外れた場合の着地 |
| --- | --- | --- | --- |
| RQ1 | 空間熱干渉はどの条件で、どの程度現れるか | 片側負荷ですぐ隣のアイドルノードが約 +10℃、離れたノードはほぼ 0。ファンなしの両側負荷では約84℃で頭打ちになり、干渉はクロック低下に現れる。ファンでスロットリング未満に保てば温度に現れる | 干渉が問題になる条件を定量化したこと自体を貢献にし、RQ3 を主軸にする |
| RQ2 | H を状態に持つ KF は予測を改善するか | 干渉を受ける側(アイドルの隣接ノード)で Self-only より大きく改善。負荷ノード自身では差が小さい(IPSJ で差が小さかった理由) | σ が干渉の変化を捉えるかを主な評価にする |
| RQ3 | 予測 + 動的マージンでファンを制御すると、安全を保ちつつ稼働を減らせるか | 常時ON より稼働率を大きく削減(80℃超過 0 のまま)。しきい値 ON-OFF よりオーバーシュートが小さい。Self-only + 固定マージンより同じ安全性で稼働が少ない | 「同じ稼働でより安全」で比較する |
| RQ4 | (余裕があれば)負荷の集約配置でファン稼働を減らせるか | 熱いノードを隣同士にまとめ、空きノードを離す方が有利 | 今後の課題に回す |


## 11/14 時点の結果と着地(結果を見る前に決めた「外れた場合の着地」に従う)

| RQ | 結果 | 着地 |
| --- | --- | --- |
| RQ1 | 開放(机)・ラックとも干渉はほぼゼロ(3 実験。B と C の上がり方が同じ=共通の室温変化) | 外れ → 「干渉が問題になる条件の線引き」を貢献に。IPSJ の干渉は排気を向けて覆った条件によるもの |
| RQ2 | KF+H は改善せず(A は偶然の負の c で悪化)。σ は一定で動的マージンは実質固定 | 外れ。限界として書く。予測の外れの主因は「30 秒以内の負荷の変化」で、σ はそれを含まない |
| RQ3 | 11/14 夜の比較実験(`experiments/20261114_compare`)で決まる | 差が出なければ「同じ稼働でより安全か」で比べる。それでも差がなければそう書く |
| RQ4 | やらない | 今後の課題。ラックでは干渉がないので配置の効果も小さいはず。囲った筐体や共有ファン(1 台で数台を冷やす)なら効く |

結論の案(11/14 夜、レオと合意):①干渉の線引き ②予測制御の効果(主役、RQ3)③限界(干渉がないと動的マージンは固定と同じ、σ が負荷変化を含まない)と次の一手。
看板は「空間熱干渉を考慮した温度制御」から「予測に基づくファン制御の実機評価」に移る → タイトル・1 章が変わるので先生に伝える。

ファンを減らす理由:PoE+ HAT のファンの電力は PoE 電流で見えない(夜間データのアイドル区間でファン ON の方が 8〜17 mA 少ない。CPU が冷えて漏れ電流が減るためと推測、未確認)。電力では説明できない → 寿命(稼働時間)・騒音を主にし、電力は大きいファンへの応用として書く案(レオが決める)。ON/OFF の回数とのトレードオフは考察へ。

次の手(11/14 夜に合意):
- 案A:段ボールの箱で囲った筐体を模擬し、干渉と提案手法を評価。現実の筐体(屋外ボックス・小型ケース)を真似て吸気口・排気口を付け、理由と条件を先に書く。B と C の差で「隣の排熱」と「箱全体の昇温」を分ける。箱内の温度も測る。出なければ「囲っても出ない」と書く
- 案B:マージンに「今から負荷が最大に跳ねたら Δ 秒で何℃上がるか」を入れ、負荷が低いほどマージンを大きくする。夜間データの前半で決め、後半で評価

## 実験(3台:A=負荷側、B=A のすぐ隣、C=離れた位置。各条件 約20分 × 3回以上)

| 実験 | 条件 | RQ |
| --- | --- | --- |
| 1 干渉の特性 | ファンなし / 常時ON × {A だけ負荷, A・B 両方負荷} | RQ1 |
| 2 予測精度 | 実験1のログで Self-only・坂本型・提案を比較。評価対象は A と B の両方 | RQ2 |
| 3 ファン制御 | 負荷パターン固定(A → A+B → B の切替を含む)× {ファンなし, 常時ON, しきい値ON-OFF, Self-only+固定マージン, 提案} | RQ3 |
| 4 配置 | 同じ総負荷で分散 vs 集約 | RQ4 |

必ず記録する:温度、CPU使用率、CPUクロック、`get_throttled`、ファン状態、室温、負荷の開始・終了時刻。

指標:MAE・RMSE(全区間と干渉区間)、最高温度、80℃超過時間、スロットリング時間、ファン稼働率、ON/OFF回数、マージンと σ の時系列。

## やらないこと

別手法(MPC・強化学習)への乗り換え、PWM 速度制御、4台以上での本実験、パラメータの細かいチューニング。
