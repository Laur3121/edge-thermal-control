## 7 章(評価)

1. 同定と評価に別のデータを使ったのはなぜ? 何と何を分けた?
   - 要点:同じデータだとモデルがそのデータに合わせ込まれ、誤差を小さく見積もる(IPSJ の課題)。ランダムの実験の前半で同定、後半で評価。別の日(11/13 のステップ)でも試した
2. 30 秒先の誤差は「入力一定」で約 0.7℃、「切り替え」で約 4℃。この差はどこから来る? どの手法でも避けられないのはなぜ?
   - 要点:30 秒の間の負荷・ファンは今のまま続くと仮定している。切り替えがあると仮定が外れる。未来の負荷は分からないので、モデルを良くしても消えない
3. 提案手法の σ が一定になったのはなぜ? そのとき「動的マージン」はどうなる?
   - 要点:σ を動かす仕組み(適応ノイズ)は H にだけ加わり、c を通してしか温度に効かない。c≈0 だと温度の不確かさは定常値に収束 → マージンは固定と同じ
4. 比較実験で「提案 38%、しきい値 40%」。これを「提案の方が良い」と言わないのはなぜ?
   - 要点:差が小さく、ノードによって大小が入れ替わる。シミュレーションで設定を変えると曲線がほぼ重なる → 違いは方式ではなく「80℃ にどこまで近づけるか」の設定
5. 遅い冷却のシミュレーションで、むだ時間が長いとしきい値方式の稼働が増えるのはなぜ?
   - 要点:ファンが効くまでの間も温度が上がるので、しきい値を下げて早めに回すしかない。予測は遅れの後の温度を見て、必要なときだけ回せる
6. 1 次遅れで「事前に決めた判断」が逆に悪くなった理由は? 「ぎりぎりまで待つ判断」を主の結果にしないのはなぜ?
   - 要点:先読み 270 秒の間ずっと OFF と仮定するので悲観的すぎ、早くから回し続ける。待つ判断は結果を見てから足したので、主の結果にすると後付けになる

## 1 章・4 章(背景・予備調査)

1. 研究の直接の対象は? データセンタとはどうつながる? 「データセンタで有効」と言わないのはなぜ?
   - 要点:空調のない棚や箱のエッジ機器。再循環=干渉、空調=遅い冷却、サーバのファン=速い冷却という構造が共通。データセンタで実験していないので「示唆」まで
2. IPSJ の課題を3つ挙げて、それぞれ特研 II でどう直した?
   - 要点:未来の実測値 → 今の値が続くと仮定。同定と評価が同じ → 別データ。b が負 → 使用率を区間平均・スロットリング区間を除く。オフライン評価 → 実機の閉ループ。条件の記録 → 室温・複数回・ランダム順
3. IPSJ では +12℃ の干渉があったのに、今回は 0.4℃。何が違う?
   - 要点:IPSJ は密閉したプラスチックの容器(排熱がこもる)。今回は開いたラック・机の上。B と C の上昇が同じ → 部屋全体の変化

## 5 章(手法)

1. a、b、e、d はそれぞれ何を表す? 物理的に正しい符号・範囲は?
   - 要点:a = exp(−Δt/τ) 熱の残り方(0<a<1)、b 負荷の加熱(>0)、e ファンの冷却(<0)、d 待機電力の加熱
2. Δ = 30 秒の根拠は?
   - 要点:ファンの応答(5 秒以内)より長く、時定数(65〜103 秒)より短い
3. α = 2、δ = 0.5℃ の根拠は?
   - 要点:正規分布なら予測 + 2σ を超える確率は約 2.3%。δ はセンサの刻み(0.49℃)
4. 80℃ の根拠は?(新しく書いた所)
   - 要点:公式の上限は 85℃(強制的に下げる)。実測では 79.9℃ でソフトの温度制限が有効になり、80℃ を超えるとクロックが 1.8 GHz から下がり始めた → 性能低下が始まる 80℃

## 予備審査の想定質問(答え方の方針)

| 質問 | 答えの骨組み |
|---|---|
| 小規模でやる意味は?(IPSJ でも聞かれた) | 直接の対象は空調のないエッジ機器。広げた先はデータセンタの遅い冷却。安価な実機で予測から制御まで確かめられる |
| 干渉がないなら H は何のため? | 干渉が出る環境(囲い)では必要になる。開いた環境では c=0 になり、手法は自動的に温度だけの KF に戻る(害はない)。囲いでの評価は 12 月 |
| しきい値方式と同じなら、提案の意味は? | 速いファンでは差がない、という結果自体が「いつ予測が要るか」の線引き。シミュレーションでは 15〜30 秒以上遅い冷却で予測が有効。正直に示した |
| stress-ng は現実的か | 同定には入力が正確に分かる人工負荷が必要。評価は実アプリ(動画変換など)でも 12 月に行う |
| 室温が変わる影響は? | 室温を記録し、室温からの上昇分でモデル化。恒温室はないので、残る影響は限界として書いた |
| ファンを減らす意味は? | 寿命は軸受けのグリースで決まり稼働時間で表される(Kim ら 1996)。騒音。PoE+ HAT のファンの電力は小さく、PoE の電流では見えなかった(電力は大きなファンでの話) |
| ON/OFF を繰り返すと逆に寿命が縮まないか | 最小 ON 30 秒とヒステリシスで、20 分あたり約 15〜18 回に抑えた。起動回数と寿命の関係の文献はまだ見つけていない(正直に言う) |
| 結果は1晩だけでは? | 5 条件 × 3 巡 × 3 台 = 各条件 9 回。順番はランダム。ただし 1 晩なので、12 月に追加する |
